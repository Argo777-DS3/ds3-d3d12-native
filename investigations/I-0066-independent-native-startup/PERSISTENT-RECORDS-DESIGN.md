# Persistent records for unchanged models: collect (C7) and prepare (C4), design (pilot, 2026-10-12)

Why: D-0167 (60 frames/s first). The engine thread costs about 55 ms a frame at S1 after cR3 (PILOT-WORK-PLAN, amendment by D-0167): collect 26.5 ms, prepare 15.4 ms, UI 6.6 ms. This sheet records two read-only studies made for the pilot by fresh Opus agents (2026-10-12, worktree at `5aa28f70`), checked against the code where the pilot acted on them. **R** = read in the code, **I** = inferred. Anchors are `native/frame/game_bootstrap.cpp` (GB) unless named. Nothing here was measured unless a run is cited.

## 1. Collect: a persistent per-model record (C7)

**Findings.**

1. **R. The content readers linked into the module used `ReadProcessMemory`.** `ds3content::Read` (`native/content/acquire.cpp`) was RPM on the current process; `game_model_selection.cpp` (`ReadCurrentModelInputsAt`, `ReadModelFadeStateAt`, `ReadModelParameterAnimations`, `ReadModelWetMaterialParameters`, `ReadModelPreparationFlagsAt`, `ReadModelDecalChoice`), `game_scene_geometry.cpp` and `scene_ingress.cpp` call it. Entry 1132 had replaced RPM by an SEH-guarded copy only inside GB. **I:** about 45 system calls per model and 3 per mesh, 8 to 10 thousand per collect, probably most of ModelAdmission (5.0 ms) and MeshLookups (2.0 ms). **Done as C7-0** (commit after `142c81e3`: `ds3content::SetProcessRead`, the module installs its guarded copy); measured in Native1379.
2. **R. Placement and the other pass-through fields feed no mesh computation**; only `instances[]` feeds a mesh output (instance blocks). C-5 (`NoteNativeModelReuse`) hashes placement, pose pointers and instance bytes but not the material bytes, the `material+0xD0` block or the texture versions, so 113 of 126 is not a bound on mesh-record reuse in either direction.
3. **R. Scene, view and instance blocks are per scene or per model but copied into every mesh** (tables built at GB `:4036-4055` in the study's numbering, read back by prepare from the mesh): about 98 `shared_ptr` copies per mesh, **I** a large share of MeshBlocks (7.0 ms) and Teardown (2.4 ms).
4. **R. The admission is mostly a function of validated inputs**; the exceptions are engine virtual calls (MatDyn providers at `+0x360` vt+0x70 and `+0x370` vt+0x30, instance lighting `32A80`, engine-registry texture lookups). Failures are never stored (P6 rule).

**Per phase** (what is recomputed per frame and how a change is detected before the work):

| Phase (ms at S1) | Changes per frame | Detection |
|---|---|---|
| ModelAdmission 5.0 | fade, group keys, pose and stream versions | recompute every frame (cheap after C7-0); reuse the instance table when its bytes are equal |
| MeshLookups 2.0 | rarely (cloth yes) | one 0x258-byte material read per mesh compared with `memcmp`; a new atomic `model_registry_epoch`; stream and cloth version pointers |
| MeshPrograms 0.1 | no | `program_registry_generation` + `prefer_channel` |
| MeshTextures 5.8 | **I** rarely at S1 | a texture key per record (`texture_registry_generation`, `TextureIngress::Version`, registry root, scene copy, common images, FaceGen record); first-candidate holders re-read as P4b; rolling revalidation for unobserved registry mutators |
| MeshShaderTex 1.2 | no | follows the texture key |
| MeshMatDyn 1.4 | **I** unknown natively | `memcmp` of `+0xD0..+0x4F8` and its arrays; meshes whose flags call a provider are volatile (always recomputed) |
| MeshBlocks 7.0 | camera when moving | after C7-1 the mesh keeps numeric blocks only; scene and view tables carried when the camera bytes are equal |
| Passes 1.2 | yes (time) | per frame |
| Teardown 2.4 | | a shared mesh set: one decrement per model |

Stays per frame: traversal, culling and visibility calls, the candidate build (PhantomParam, cloth set), all model-level fields, the validation reads, provider meshes, Passes. **R:** LOD is not camera-dependent natively (engine fade variants plus `model+0xB4`).

**Record.** Key `(entity, model)` in a main store and an offscreen store `(holder, entity, model)`; the key only places the record, validity comes from the validated inputs (so address reuse with equal inputs is a correct hit). Contents: an immutable `MeshSet` (the meshes without scene, view and instance arrays), LOD mask, `prefer_channel`, storage pointer, pose, stream and cloth versions, mesh and material-pointer table bytes, param-anim row bytes, wet values, outcome counts, `last_seen` and the epochs seen; per mesh the material bytes, the `+0xD0` image, a volatile bit and the texture key. A per-collect scene key (category scalar and override, wet catalogue, common images, main or offscreen). `NativeSelectedModel` stays a per-frame value holding the mesh set (17 `.meshes` sites to adapt). Partial hits recompute only the invalid tiers. Lifetime: 120-collect TTL; when `model_registry_epoch` moves (storage add or retire, material or layout erase, pose, stream erase, cloth), records not visited this collect are dropped; `ResetNativeSelectedScene` and `Close` clear both stores. Threads: hooks only bump atomics; the main store is owner-thread only; the offscreen store under `native_offscreen_collect_lock`; records are immutable, held by scenes on the worker.

**Guard and flags.** `collect-shadow.flag` extended: each shadow turn rebuilds every reused model by the K path and compares field by field (`native_collect_record_mismatch {tier, model, mesh, field}`), dropping the record on a mismatch; rolling revalidation of 1/32 of the records per collect in product builds (`revalidation_changed` must stay 0). A/B: `rebuild-collect-records.flag`. New counters go before `PrepRows` in `collect_profile.h` (the split row prints counters below that index) and `Get-CollectSplit.ps1` follows.

**Commits.** C7-0 (done), C7-1 (scene and view blocks from the scene tables, instance blocks from the model table; prepare looks them up by `NativeProgramKey`), cP6 (R8B S1 group snapshot), C7-M (measurement: changes per tier), C7-2 (store, validation, shell, behind the flag), C7-3 (epoch hooks, Reset, Close), C7-4 (offscreen store), C7-5 (default after the witnesses). **I:** idle collect at S1 about 4 to 7 ms afterwards; a moving camera adds 0.5 to 1.5 ms; streaming falls back to today's cost.

## 2. Prepare: persistent prepared draws (C4)

**Frame-level constants leave the draw.** **R:** every frame-level block is today copied and given a CBV in each draw's table (`model_draw.cpp` write path). Frame blocks: VS b0 `cbMatrixWVP` (camera; velocity matrices on the Velo pass), VS/PS b8 `cbSceneParam` (deferred; forward variant with four words zeroed), VS/PS b9 `cbPerFrame` (time). **R:** packing writes source ranges into a zeroed buffer of the programme's declared size and truncates, so each programme's packed bytes are a prefix of one canonical buffer per pass, stage and register: one buffer per pass serves every draw. Model or mesh blocks (b1 tiling, b2 matdyn, b3 numeric, b4 instance, b5/b6/b12 palettes, b7 model parameters, b11 scroll, forward b5/b6 light and fog, PS b0 HDR scale) stay in the draw.

**C4-1, root CBVs.** Keep root parameters 0 to 3 (VS table, PS table, samplers); split each table's CBV range around the frame registers with explicit offsets (table slot = register); add five root CBVs (VS b0, b8, b9; PS b8, b9; 14 DWORDs of root). The draw input marks frame blocks (`frame_block` kind) which `Prepare` does not copy; `Encode` takes the pass's five GPU addresses and refuses a missing one. Prepare produces the canonical blocks once per call; the worker allocates them from the slot's upload arena (the arena belongs to the recording thread) per pass (main, Velo, each menu view). **I:** 1 to 1.5 ms off prepare by itself (about 2.8 MB of copies and 3 to 5 of the 10 CBV writes per draw).

**C4-2, the cache.** One entry per row (entity, model, part, mesh ordinal, recipe, engine pass, fade), main view only. Reuse needs an equal model version (a per-entity record holding the cP6 snapshot by value: placement, cloth world, group state, wind, instances, colour, phantom fields, scroll, pose, stream and geometry versions, forward-light entries after cP7; compared byte for byte, R-P1) and an equal row key (programmes, layout, geometry views and generations, texture and scene record pointers, matdyn bytes, wet, tiling, pose policy flags, cull class), under unchanged global epochs (device epoch, programme registry, sampler bank, pixel policy, category scalar, velocity rows, the frame sources' written masks, the A/B flags). Sweep after 8 unused prepares, LRU bound, counters (R-P3). **Required fix:** each draw today holds the whole scene (`cpu_owners` gets the scene); a persistent draw must hold only what it references. **Prerequisite:** cP6, since prepare still reads group and wind live.

**Lifetime.** A draw is immutable after `Prepare` and held by the cache, the frame input, the job and each slot; L2 already covers two slots sharing one draw, so no ring change. **R-P2 amended:** a GPU range may live across frames only inside an immutable prepared draw written once and released by its last holder through the ticket path; per-frame data lives only in the slot's arena. A second allocation stream for persistent constants and descriptors avoids pinning per-frame chunks; compaction only if a long run shows growth.

**Guard, flags, commits.** Shadow under `prepare-shadow.flag`: a round-robin 1/30 of the reused rows rebuilt and compared (payload bytes, masks, SRV sources, samplers, pipeline words, geometry, stencil), `native_persistent_draw_mismatch` on a difference. Flags: `persistent-draws.flag` (with a dry-run that only counts would-be hits), later the default with `no-persistent-draws.flag`; `legacy-frame-cbv.flag` for C4-1; `rebuild-prepare.flag` turns both off. Commits: C4-1, C4-2 (after cP2 and cP6), C4-3 (shadow), C4-4 (derive a draw whose only change is the palette or b7), C4-5 (default, M-run). **I:** prepare at S1 about 4 ms with 113 of 126 models unchanged (2.5 to 3 with C4-4; 6.5 with 40 % of rows changed). **Correction to the prepare sheet section 1:** C-5 leaves out group state, wind, matdyn, tiling and texture records, so 113/126 is an upper bound; the dry run (PD-0) measures the real hit rate first.

**PD-0 measured (Native1429, 2026-10-12, `-PrepareDryRun`: prepare-dryrun.flag, no reuse).** At S1, of 1,062 complete main-view rows a prepare, 896 (84 %) build a draw input equal by content to the previous prepare's same row (entity, model, mesh, fade, engine pass, recipe, occurrence; frame blocks by size only, since the pass binds its own copy), and **0** equal by payload identity: the pose palettes (call-local `share`), the instance blocks and the per-row model parameters (VS b7, PS b7, forward b5/b6) are new objects every frame. `PrepareNativeModelDraw` takes 1.55 ms on those 896 rows; the whole row about 84 % of the 9.2 ms. So the cache must be keyed on the inputs before the row is built (a per-model version, as above), not on the built input: an equality check on the built input saves at most the 1.55 ms. The dry run's digests cost 1.4 ms (prepare 10.6 ms under the flag); the identity rate is an upper bound (raw pointers), the hit time a lower bound (whole microseconds per row). Opus review: no defect; nits applied (the mode row records the flag, the split script reads older rows).


**C4-2 input inventory (read from `PrepareNativeModelFrame`, 2026-10-12, after PD-0).** What one main-view row reads, so the row key and the model version cover it. Row: `prepared` model, mesh, fade, engine pass, recipe, tiling values and stages, scroll version. Mesh: layout (elements and their availability), slice (strides, vertex count and offset, cull class), geometry binding, `programs` (recipe programme set, interfaces, read analyses, policy: depth write, blend mode, alpha ref; its palette, matdyn and tiling caches; damage and generated parameters), pose policy (cloth flag, flags), current patch index, numeric blocks, dynamic bytes and coverage, material class, wet activation, texture and scene texture bindings, shader textures, cloth stream. Model: pose and previous pose (their palette objects, row counts, cloth and cancel), streams and authored geometry bytes (palette index checks, kept per Programs), placement, cloth world, engine bytes (group 0x190, animation block, flags), animation presence, draw colour, phantom fields, the fade intent (enabled, opacity), forward light and fog entries, instance block of the fade, texture scroll, ordinary category. Scene: sampler bank and its generation, pixel policy, category scalar, default parameter row, velocity scale (Velo PS b7); frame roots (view, scene, per-frame, forward scene, velocity matrices) only by their packed size, the pass binds its own copy. Global: `prepare_rebuild`, the device, the target and depth formats. Witness-only reads (asm part, names, sample counters) need no key. PD-0's identity result follows from the call-local blocks (palettes, frame blocks) and per-row productions (VS/PS b7, forward b5/b6): their sources (pose palette objects, engine bytes, light entries) are what the version compares, not the packed blocks.

## 6. The UI capture and the 60 frames/s mark (2026-10-12, pilot thread)

After cR6 the engine thread was the only limit at S1 (present 0.5 ms, GPU wait 1 ms): before-update 3.9, update with collect 5.2, UI capture 5.6, `Clear()` 2.0 ms (Native1413, 59.1 frames/s). **R:** the UI units read every engine field with `ReadProcessMemory` (one system call per `Load`: `game_ui_session`, `game_ui_cpu_shape_context`, `game_ui_glyph_context`, `game_ui_image_owner`, `game_ui_mesh_owner`); the C7-0 rule now applies to them (`ds3content::Read`, the module's guarded in-process copy). ## 7. C4-2: the main view's prepared draws kept across prepares (2026-10-12, pilot thread « Cache des draws préparés »)

| Step | What changed | Prepare (ms) | S1 frames/s | Run |
|---|---|---|---|---|
| A/B base, same build | `no-persistent-draws.flag` (runner `-NoPersistentDraws`): every row prepared afresh | 9.09 | 59.98 | Native1435 |
| C4-2a + C4-2 | kept draws, per-draw descriptor ranges | **3.92** | 60.0 | Native1434 |
| after the second review | ranges by epoch, returned through their own list, heap restarted when empty | 3.97 | 60.0 | Native1436 |

**C4-2a (branch of the previous pilot, `claude/c4-2a-reencode`).** A draw with bounded descriptor CBVs (VS b5, b6, b7, b12; PS b4, written into its own table at encode) may be encoded again in a later numbered frame once the GPU has finished the previous one (`NativeModelConstantUploads` carries `FrameRing::Numbered` and `CompletedThrough`; a refusal leaves the state unchanged). With one frame slot (the default) every later frame qualifies; `model_draw_test` covers kept, overlapping, same-frame and unnumbered encodes.

**C4-2 (R, `PrepareNativeModelFrame`, `NativeKeptDraws`).** A main-view row (entity, model, mesh, fade, engine pass, recipe, occurrence) takes its kept draw when: its model's version is unchanged (`NativeKeptModelInputs`: the C7-2 mesh set by identity, which carries every mesh input since the set is immutable; geometry storage, pose and previous pose snapshots and stream version by identity, held; engine bytes, forward light and fog, placement, cloth world, category, draw colour, scroll, fade intents, animation presence, phantom fields and asm part by value), its tiling values and its VS and PS instance blocks (b4) are equal, and the scene inputs every row reads are unchanged (`NativeKeptEpoch`: sampler bank and generation, device, pixel policy, category scalar, default parameter row, velocity presence and scale, simulation time presence; a change drops every draw). The frame registers are produced again for each hit (the same `frame_block_of` as a fresh row), so the view's canonical blocks are this frame's; a refused one rebuilds the row. A kept draw holds its mesh set, geometry, streams and sampler bank, not the scene. Kept draws unused for 8 prepares and model records unseen for 120 are dropped; a reset (area change, title) drops them at the next main prepare; `CloseNativeKeptDraws` releases them before the device closes. Enabled with one frame slot only (not under `rebuild-prepare`, `prepare-dryrun` or `no-persistent-draws`). Under `prepare-shadow` every 30th hit is built again and compared field by field (`NativeKeptInputDifference`: programmes, geometry, state, every constant payload, SRV and sampler; `native_persistent_draw_mismatch`).

**Descriptor ranges (Native1431).** The global shader-visible heap was handed out in 8192-descriptor chunks shared by a frame's draws and returned when all of them were gone; kept draws pinned all 32 chunks (`global_chunks_peak` 32 against 13 at Native1427). Each draw now takes its own range (rounded to 16 descriptors, free lists by size, split from a larger free range once the heap's untouched end is used), returned by ticket when that draw is gone: peak 10 chunk equivalents at Native1434, 0 per-draw table draws.

**Measured.** Native1434 against Native1435 (S1, `-Measure -NoDebugLayer`, same build, High Wall): prepare 9.09 -> 3.92 ms (rows: 837 hits, 221 rebuilt for a moved model version, 15 incomplete, 4 for their own inputs, out of 1,077); the worker's record 2.45 -> 2.39 ms; per-draw constant blocks 8,460 -> 1,860, SRV bindings 6,126 -> 1,248 a prepare; the kept-draw lookup and the frame registers of the hits 0.88 ms. Both runs hold 60 frames/s at the game's cadence; the worker's freed time shows as GPU wait (1.0 -> 6.8 ms), which is slack, not new work. The model versions that moved (Native1433, per prepare): about 18.5 models whose C7-2 mesh set was rebuilt (records invalid by the 500 ms texture fallback expiry, volatile models, the 1/32 revalidation, which replaces the set even when equal) and about 8 posed models (animation).

**Witnesses.** Native1431 (first build, High Wall protocol, debug layer, both shadows, menus, Equipment page) and Native1433 (final build, same protocol): exit 0, 0 debug errors, 0 kept-draw mismatches (about 15,600 shadow checks every 600 prepares), 0 prepare-cache mismatches, 0 collect-shadow mismatches (185 and 187 scenes), restorations ok. Native1430 stopped at the first in-game prepare: a kept draw held a null owner (a model without a stream version), refused by the draw's own check (fixed: only present owners are held).

**Opus reviews (fresh agents).** First review: one blocker (the null owner, already fixed by then), two defects (the pinned descriptor chunks, the reset only processed by a prepare with rows), nits; all applied (per-draw ranges, the reset check before the early returns, the frame registers checked before the shadow decision so a refused one is a rebuild and not a mismatch, the guard inert while an exception unwinds, eviction of unused draws past 16,384 before a clear, frame refusals counted apart). Checked with no finding: every row input is covered by the mesh set identity, the model inputs, the row inputs, the epoch or the per-hit frame registers; a kept draw references only what it holds; one slot makes re-encoding sound.

**Second Opus review (the fixes): no blocker.** Applied: a range returns with its device epoch (a device change and back must not return an old range); returns go through a separately locked list drained at the next allocation (a draw released on the recording thread no longer takes the cache lock); when no range is in use the heap starts afresh (free ranges are never merged; this heals fragmentation at each area change), and the audit row carries the heap's used extent (`global_bump_peak`) beside the in-use peak; `DeviceQueues::CollectCompleted` releases completed owners in one pass (an erase per entry was quadratic when a reset drops thousands of kept draws); the shadow guard compares the exception count captured at its construction; past the 16,384 bound unused draws are evicted and no new draw is stored (no clear). Native1436 (S1, final build): prepare 3.97 ms, 837.5 hits a prepare, 60.0 frames/s, 0 per-draw table draws, in-use and extent peaks 10-12 and 13; Native1437 (Firelink protocol: teleport and area streaming, cloth NPCs, white phantom, camera turns, debug layer, both shadows): exit 0, 0 debug errors, 0 kept-draw mismatches (11,931 shadow checks in the last 600 prepares), 0 collect-shadow mismatches over 342 scenes, the extent back to 7 chunk equivalents after the area change, restorations ok. Noted: `Clear()` 2.79 ms at Native1436 against 1.24 at Native1434 (the wait for the worker's previous job, whose time is mostly the GPU wait at 60 frames/s); to watch in the next measures.

**Open.** The rebuilt-model misses (C7-2 could keep the set's identity when a revalidation or a fallback refresh gives equal meshes; about 18 models a frame), then the posed models (a palette change could derive the draw, design section 2 C4-4); kept draws with two frame slots (a second table per draw, or a re-prepare from the kept input).
