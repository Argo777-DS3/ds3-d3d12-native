# Wave 1 of the master plan: preparation of the first slices of the seven families (static, 2026-10-11)

Request (coordinator, 2026-10-11): prepare wave 1 of [D3D12-MASTER-PLAN](../I-0068-static-yebis-ffx-lights-spec/D3D12-MASTER-PLAN.md) §4 the way phases A to C and workstream K were prepared ([D3D12-PHASES-A-C-PREP](D3D12-PHASES-A-C-PREP.md), [COLLECT-K-PREP](COLLECT-K-PREP.md)): the creation door, lights and wind of the effects; glow 1 to 3; the shadow producers; the tessellation parse; the SSAO parameters; the YEBIS skeleton with tone map and gamma; Scaleform F8a and F9. For each: files, functions and lines, dependencies, a reversible commit order, measures and witnesses. No native code was changed, nothing was launched.

Labels: **observed** = read in the native tree at main `aedb93f7` (line numbers are that tree's and will move; the code mapping was done by four read-only readers whose key claims I re-checked by hand); **note** = a statement of the linked design note; **proposed** = this note's design; **open** = needs a read or a measurement first. Abbreviations: `GB` = `native/frame/game_bootstrap.cpp`, `SP` = `native/renderer/scene_pass.cpp`, `MD` = `native/renderer/model_draw.cpp`, `UI` = `native/frame/game_ui_session.cpp`, `LP` = `native/world/light_producers.cpp`.

## 0. Answer first

1. **The wave is not one block.** Reading the code splits it into four kinds of work with different prerequisites: **(A) engine-side or UI-only slices** that need no D3D12 work (effects N1-N4, Scaleform F8a/F9) and can start now; **(B) CPU producers with golden tests and no visible change** (shadow gates, shadow state and constant images, `AoParams`/`AoView`, `Banks::Glow` and the glow gate, `cbTessScene`, `cbPNTriangles` with the GX04 parse, the YEBIS bank-struct builder); **(C) one shared preparation of the model-draw envelope** (render-target count 0/1/2/6, optional depth format, hull/domain stages, patch topology), which glow RT1, tessellation and the shadow atlas all need and which phase C (R6, R7, R9) edits in the same file; **(D) GPU slices** that sit on (C) (glow RT1 and resources, the tessellation PSO and draw, the SSAO resources, the shadow atlas, the gamma pass, the YEBIS tone-map path).
2. **Five findings of the reading change the plan** (none contradicts a design note):
   - **The GX04 parse alone breaks the veil.** Once material `+0x250` is non-zero the mesh gets `base_deformation` 3 or 4 and is refused at gate 27 (`GB:4515-4517`), because `SelectModelPrograms` returns Unsupported for any deformation (`content/model_programs.cpp:40-42`): the veil stops drawing instead of drawing flat. The parse must ship with a flat fallback (T1) or together with T2/T3.
   - **Shadow step 2 has no native owner.** Nothing in `native/frame` calls or transcribes `1B5720`, `23A0C0` or `1B6B80`; the cascade matrices, `CascadeSelectDist` and the `+0x110` flag exist only as reads of an engine state snapshot in `LP`. The producers `PerScene`, `BlurParam`, `ShadowFieldsFromBanks` are driven by call-argument regions and cannot be called with native data as they are. So "shadow producers" is a re-expression of the producers on a native state struct plus a decision on how the cascade fit is obtained; it is larger than a gate read. Step 4 (casters) touches six hard-coded shader-pass gates and moves to wave 3.
   - **The model-draw envelope is shared by three slices.** `MD:272` accepts only 1 or 6 render targets, `MD:20-23` only vertex and pixel stages, the root signature denies hull/domain/geometry access (`MD:200-203`), `gbuffer_encoder.h:46` rejects patch topologies. Glow RT1 (2 targets), tessellation (HS/DS, patch list) and the shadow atlas (0 targets, D16) each need a change to the same validator and PSO key as phase C's R9: do it **once** (commit W0a).
   - **There is no native colour or gamma path yet.** The UI is drawn straight into the back buffer (`SP:1629-1633`); the brightness intent is computed (`GB:7344-7358`, `native_colour_settings`) and nothing reads it. A legacy `FinalDisplay` pass exists (`SP:464-483`, `2034-2044`) but no live producer feeds it. The gamma pass is independent of YEBIS and can ship first.
   - **The YEBIS slice cannot be validated piecewise.** Nothing of the HAL, `CPostEffect` or the driver exists natively; `Banks` exposes floats only (no integer or flag accessor for the Setting Info words); there is no readable-depth copy; and the library cannot be run in parts, so the first image already needs the whole chain. It is the last and riskiest trunk of the wave.
3. **Order of the wave** (details in §4): W0 shared preparation (envelope, effect-input struct); W1-W2 Scaleform; W3 gamma; W4 effects N1-N4; W5 the producers; W6 glow; W7 tessellation; W8 SSAO resources; W9 shadow atlas; W10 YEBIS. Each commit builds, keeps the previous behaviour behind a flag file, and is judged by its structural counter first.
4. **Interaction with phases B, C and K**: B2a/B2b (arena and retirement hooks) are merged; the wave's GPU slices want R9's hashed PSO key (phase C1) before they extend the key, and K touches `AdmitNativeModelCandidate`/`PrepareNativeSelectedPasses`, where W5 adds collect-side inputs (§4.3).

## 6. Risks

1. **The veil regression** if the GX04 parse lands without the flat fallback (T1b): a visible loss, not a fidelity gap.
2. **Shadow step 2 may not be solvable by transcription alone**: calling the engine's fit needs a constructed `GXCascadedShadowScene`; a wrong choice delays every shadow slice. Decide in S2a, with the existing `light_check shadow=` route as oracle.
3. **Shared files**: `game_bootstrap.cpp`, `scene_pass.cpp` and `model_draw.cpp` are edited by phase C, K and five items here; keep new logic in new files (shadow state, glow inputs, tess producers, gamma, YEBIS), keep call-site edits short and use the fixed insertion points of this note.
4. **Descriptor and RTV heap capacity**: `native_light_rtvs_` is full (8); every new feature creates its own heap now and moves to the global heaps with R6.
5. **Inert resources cost memory** (the shadow atlas 128 MiB): behind flags, created lazily when the consumer exists.
6. **YEBIS first image**: the whole chain runs at once; its draw-list digest (YB1) is the only structural check before the image is judged.
7. **Effects N1**: a missed GX statement in the transcriptions crashes on the absent `[144961AB0]`; N1a lands behind its flag and with the PHASE1 crash guard.
