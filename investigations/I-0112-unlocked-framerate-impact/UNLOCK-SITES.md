# I-0112: the unlock sites read one by one (evidence for UNLOCK-READY)

> Read by a Sonnet `ghidra-research` subagent for the study thread (2026-10-30, GhidraMCP on Thomas's Ghidra, read-only), kept as
> it returned it. Non-canonical until a pilot rereads what a fix depends on (WORKFLOW « Roles and delegation »). Checked by the
> study thread: the game step `1408F2CA0` hands `[[0x14489DD10]+0x26C]` to the selector and its own `param_2` to the rest; `1405E6580`
> keeps its XMM1 argument (`MOVAPS XMM7,XMM1` at `1405E65B0`) and hands it on: its dt.

Method: `mcp__ghidra__get_program_info` (DarkSoulsIII.exe, sha256 ef5e07c5...), `decompile_function_by_address`, `get_xrefs_to`,
`get_function_calls`, `read_memory`, `disassemble_function` on Thomas's Ghidra. From the same Ghidra server (port 8080) I also used the
read-only HTTP endpoints `decompile_function?address=`, `read_memory?address=&length=` to dump the big physics functions to the scratchpad
and grep them (no write endpoint touched). No headless Ghidra. Every entry below: OBSERVED = read in the decompile/bytes, INFERRED = my reading of the shape.

## 0. Global facts

- ALL listed functions: decompile OK, ENTRY = PLAIN PROLOGUE (OBSERVED, `read_memory` of 12 bytes at each entry; none starts with a jmp
  into 0x140EED810 / 0x144E79363 / 0x1451CEA9D / 0x144E60057). No Arxan guard at any entry. So all are hookable at the entry.
  `thunk_FUN_144e60057` appears inside bodies only as the "singleton is null" assertion path.
- Tiny leaf functions (140663300, 140663340, 14072FEC0 start `mov eax,[rip+x]` (6 bytes); 14100DDE0 starts `sub r8d,edx`): a detour needs
  RIP-relative relocation for the first three.
- Shared constants (a data redirect "C" would change every reader), OBSERVED values and reader counts (get_xrefs_to):
  - 143d7ed50 = 0x3D088889 = 1/30, 41 readers (list in section 5).
  - 143d7ed3c = 0x3C888889 = 1/60, 17 readers.
  - 143d7ef84 = 30.0, 51 readers. 143d7efa8 = 60.0, 53 readers. 143d7ed94 = 0.2, 77 readers. 143d7edcc = 0.6, 35 readers.
  - 143d7edf0 = 0.8 (29 readers), 143d7ee18 = 1.2 (22 readers), 143d7ee38 = 1.5, 143d7ed70 = 0.1 (not read).
  - ONLY exclusive constant: 1429b5b88 = 0x3C888723 (0.016666), 3 readers, all in 140EF2CE0.
- Real dt. 1408F2CA0 (the game step, `void (this, float dt(XMM1))`, vtable-called, plain prologue) builds `{vtbl 1427457d8, float}` from
  `*(float*)([0x14489DD10]+0x26C)` (NOT +0x268) and passes it to the selector 140DD4B60; it passes its own `param_2` (dt) to
  140607570, 1408FBC10, 1408FA910, 1408FA3E0, 140EE0790 (OBSERVED). Both fields are frame durations; check which one you want (+0x268 per the brief, +0x26C used here).
- Time object layout (OBSERVED, 14066BD70: `*(float*)(param_2+8)`; 140A4CDF0: `*(float*)(param_2+8)`): `{+0 vtable 0x1427457D8, +8 float dt}`;
  the destructor writes vtable 0x1427457C8. A callee takes a POINTER to it; the dt is `[ptr+8]`.
- x64 ABI reminder for float args: dt as a function parameter arrives in XMM1 (second arg) / XMM3 (fourth). 1405E6580 is OBSERVED to do
  `MOVAPS XMM7,XMM1` at 1405E65B0 then `MOVAPS XMM1,XMM7` before each callee: its decompiled `undefined4 param_2` IS the float dt.
- Generic "pre-bias" trick for additive constants (preferred over a pure post-correction when the value is branched on inside the call):
  before the original: `x_pre = x_old + c*(1-k)` with `k = dt/dt60`, c = the constant step (signed); the original then adds c: result `x_old + c*k`.
  After: if the field is still exactly x_pre (the update did not run), restore x_old. For decays `x *= r`: `x_pre = x_old * r^(k-1)`.
  Alternative without touching the state: scale a GAIN stored in an object field (`g' = 1-(1-g)^k`) around the call and restore it.
- Frequency statements ("once per frame ...") are INFERRED from shapes; a runtime counter is the only proof.
