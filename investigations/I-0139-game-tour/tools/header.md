**How a cutscene is replayed with the test launcher today.**
- A tool that clears an arbitrary event flag exists: `witness-flag.txt` beside the module holds `id value` and sets or clears one flag through the game's own setter while the game runs (`ApplyWitnessFlag`, `native/frame/game_bootstrap/04_updates_and_test_tools.inc`, both modes; `Run-AlphaCast.ps1 -SetFlag "id 0"`; one id per file, read every 15 schedule calls, the file removed once read, nothing happens before the flag manager is ready). `test-revive.txt` is not enough: it accepts only the 26 boss flags of `boss-flags.json`.
- A scene needs one to four flag changes (the boss flag, its « seen » flag, sometimes a precondition), so a replay takes several runs. The smallest tool that would fix it: a `test-flags.txt` beside the module (lines `id value`, applied when the world has run 180 frames as `test-revive.txt` is, again on F5), written by a `-SetFlags "id v;id v"` option of `Run-AlphaCast` / `Run-StartupTrace`.
- The event instances read their flags when the map loads: after changing flags, rest at a bonfire or travel so the map reloads, then `-Teleport "x y z hold"` to the trigger (hold above 0). I-0113's chair and Anor Londo notes show teleports to `c0000_*` parts work; a region centre is standable only if the geometry says so (INFERRED), so each row gives the nearest start too.
- The « seen » flag is the flag an event sets at its end and tests with a goto at its start (INFERRED, not a label in the data).
- No native run has played a cutscene (REMO-CUTSCENES-NATIVE §0 point 3; fade plates 3 and 4 are not drawn natively and a plate that never finishes could block a cutscene's start, RL8): a native replay is itself a first witness; run the original build beside it.
