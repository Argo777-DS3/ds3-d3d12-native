# K-0067 — WorldChrMan update-task registration and scheduler buckets

Status: `CONFIRMED`

## Claim

`WorldChrManImp+0x31A8..+0x33E7` embeds twelve consecutive `0x30`-byte
`SprjEzUpdateTask<SprjEzRabbitTask, WorldChrManImp>` records. Constructor stores
bind every record to the manager owner and an exact callback. Function
`0x008DBDA0` registers selected records for profiles 0 through 2 with exact
numeric phase IDs and priority zero; the bounded tail caller `0x008FA3E0`
selects profile 0.

Exact RTTI closes the scheduler object boundary:

- `SprjEzRabbitTask -> SprjEzRabbitTaskBase -> SprjEzTask -> FD4TaskBase ->
  FD4ComponentBase`;
- `SprjEzTaskProxy -> FD4TaskBase -> FD4ComponentBase`;
- `SprjTaskGroupImp` as the phase-table owner.

Rabbit virtual slot 4 sets record `+0x18` and delegates to base registration
`0x00F0F110`. The base owns a task proxy at record `+0x10`; the proxy stores
task pointer `+0x10`, phase ID `+0x18` and priority `+0x1C`. Registration
inserts it into one of `0x61` indexed timeline-group instances owned by
`SprjTaskGroupImp`. Execution bridge `0x00EBF0D0` queries endpoint group tokens
`0x00` and `0x60` and passes
them to an external execution graph.

## Limits

- Original profile and phase enum names are unknown.
- Indexed group selection and endpoint tokens are confirmed; a simple numeric
  serial execution order and within-group order are not yet proved. K-0068
  refines the startup provenance and recovers the 97 exact static names.
- The profile-0 tail caller is exact but is not claimed to be the only caller
  or the only runtime profile transition.
- No live behavior or timing-correction claim is added. LTF and TRTF are
  unchanged.
