# K-0098 — Typed ResManagerImp fan-out to exact resource repositories

Status: `CONFIRMED`

## Claim

Exact `ResManagerImp` retains a shared lookup input at `+0x128`. Six exact
repository constructors — `SprjEdfRepositoryImp`, `SprjEldRepositoryImp`,
`SprjEvdRepositoryImp`, `FfxRepositoryImp`, `OnavRepositoryImp` and
`RumblebndRepositoryImp` — directly read the published manager, perform a
repository-specific keyed lookup through that field, and retain the returned
value at repository `+0x88`.

## Proof basis

[File/resource manager boundary](../../evidence/I-0016/static/file-resource-manager-boundary/FILE-RESOURCE-MANAGER-BOUNDARY.md),
exact-build RTTI/vtables, exact constructor stores, direct global reads and
field transfers.

## Limits

This is a structural manager-to-repository binding, not proof of disk/archive
I/O, request submission, async completion, readiness, streaming order or
thread affinity. No direct `SprjFileStep`/`SprjResStep` to resource-manager
edge is recovered; that relation remains `UNKNOWN`.
