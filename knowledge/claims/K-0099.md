# K-0099 — EVD repository and file capability lifecycle

Status: `CONFIRMED`

## Claim

Exact `SprjEmkResManImp` constructs and publishes exact EVD, EDF and ELD
repository objects, then destroys and clears those three globals on its
paired teardown. Exact `SprjEvdFileCap` vtable slot 6 obtains a keyed result
through `SprjEvdRepositoryImp+0x60` and retains it at file-cap `+0x80`.
The repository's new-object path constructs exact `SprjEvdResCap`; the
file-cap destructor passes its retained result back to an EVD repository
helper for conditional destruction/release.

## Proof basis

[EVD repository/capability boundary](../../evidence/I-0016/static/evd-repository-boundary/EVD-REPOSITORY-CAPABILITY-BOUNDARY.md),
exact-build RTTI for three types, paired manager construction/teardown,
file-cap vtable slot and cleanup assembly, keyed repository helper,
and the bounded 24-row direct-global census. I-0016's validator and
manifest guard the selected exports.

## Limits

The `Evd` type name and the shared executable do not prove a direct
`SprjEventManImp` or world-resource join. The retained result may be an
existing collection member; exact payload, physical loading, completion,
readiness, task activation and schedule order remain `UNKNOWN`. The
`0x00459D00` decompilation contains bad instruction data beyond its
decoded listing and is not used to infer an event-manager edge.
