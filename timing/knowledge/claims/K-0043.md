# K-0043 — Runtime spatial-exchange ordering at target 60

Status: `CONFIRMED` within the accepted target-60 control.

## Claim

All 528 complete observed exchanges execute in the same order:
`00DD3850` entry, `00DD3A7A` forward write, `00DD3B50` entry, then
`00DD3BB2` reverse write. The descriptor-selected 48-byte block is
bit-identical at both entries within every exchange.

Two selected addresses occur. A stable-owner slot appears once in every one of
the 360 measured updates. Its reverse write is unchanged 236 times and changes
only DWORD lanes 0 and 2 in 124 exchanges. Those reverse-payload lanes match
the independently sampled player `x` and `y` fields in 360/360 updates within
`1e-5`; lane 1 does not match sampled `z`. A second slot appears in 168 updates
across 14 owners and every reverse write is unchanged within its exchange.

Incoming XMM1 lane 0 is near `1/60` in both directions for the stable slot. For
the shared slot it is near `0.5` on all 168 forward entries and near `1/60` on
all 168 reverse entries. The raw argument therefore has direction/owner-specific
regimes and is not assigned one universal elapsed-time meaning.

## Limits

This is one target-60 trial. The data confirms ordering, identity and bounded
position correlation; it does not assign the full block type or subsystem
semantics. The conditional target-165 trial crashed and is rejected, so no
cross-rate cadence, value-equivalence or defect claim follows from this record.
